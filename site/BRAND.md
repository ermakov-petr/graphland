# GraphLand visual reference

All four GraphLand pages follow the shared visual system of [Yandex Research](https://research.yandex.com/). Their white scientific introductions follow [Publications](https://research.yandex.com/publications); the same header, fonts and responsive container were checked against [About](https://research.yandex.com/about). These are measurements of the public site captured on 2026-10-08, rather than a claim of official design-system certification. A fresh reference capture on 2026-10-26 confirmed that both original logo SVG geometries, all five font files and the reference stylesheets remain unchanged. Publications retains the 48px / 40px / 30px heading scale used here; the larger homepage heading belongs to its distinct landing-page composition.

Interface text and numeric tables use YS Text; descriptive editorial text uses Merriweather Light. Heading weight is 500, regular interface text is 400, serif text is 300. H1 tracking is −0.008em on desktop and −0.004em on mobile. All four pages share one intro and typography scale: H1 is 48/48px, 40/40px, then 30/32.4px; content H2 is 32px / 24px / 24px; H3 is 24px / 18px / 18px. Editorial lead and body copy use 22px / 17px / 15px at line-height 1.5. These heading and prose roles follow the reference's inner-page and rich-text styles. Buttons have a 30px radius, with 52px / 18px type above 1600px and approximately 40px / 14px type below. The Submit accent is #fed42b, with #f5c400 on hover.

The five WOFF2 files and three SVG drawings are hosted locally under `assets/brand/`. Their source URLs, captured build and SHA-256 hashes are recorded in [provenance.json](assets/brand/provenance.json). HTML and CSS use relative URLs, including when served under `/graphland/`. Three critical font faces are preloaded; the remaining faces load on demand. Font declarations are paired with actual files for every used weight.

Content is specific to GraphLand: the comparison table, protocol explanations, filters and review disclosures retain their scientific meaning. Per the 2026-10-26 project brief, the header contains only the original two-part SVG logo: the entire wordmark links to the canonical HTTPS Yandex Research home page. Research section links, header search and the mobile navigation menu are omitted. The original logo geometry, responsive dimensions and header spacing are retained. Search placeholders and footer hover retain readable contrast; the reference's low-contrast placeholder and gray-on-black hover were not copied.

Run `python -m unittest discover -s tests/leaderboard -v` for build/data/frontend checks and `python -m unittest discover -s tests/browser -v` with the pinned Playwright requirements and Chromium installed for interaction/brand checks. Brand tests verify served font bytes, actual glyph fonts, SVG geometry, responsive boundaries and the single external logo link. A deliberate font 404 establishes that the glyph test detects fallback rather than merely reading the CSS font-family. Dialog history includes a deterministic delayed-close focus regression.

The project has four native pages with its own navigation beneath the Research header. The original logo remains the only header control. Project navigation follows Research's regular 400-weight text, 20px / 16px scale, 32px desktop gaps and gray active/hover text without a bold or underlined active state. Mobile uses 16px links with 24px column gaps as a deliberate adaptation instead of the reference's fullscreen menu. At widths up to 560px, all four sections are visible in two rows with 44px link targets; wider layouts retain the horizontal strip. Navigation does not move the page vertically. All four routes use the same page-intro, title, lead and content spacing. The former large illustrated Leaderboard hero is removed. Dataset documentation and loading examples follow the supplied GraphLand brief; OGB informs information architecture only. Python blocks use semantic syntax colors distinct from brand accents.

The common system extends through the complete page, not only its intro. Leaderboard explanations, the result legend, protocol and submission steps use white editorial sections on the same shell and spacing scale as dataset documentation. Their descriptions share the Merriweather prose scale; utility labels and tables use YS Text. Both filter groups use the same flat text-tab treatment with a thin selected underline. The catalog and leaderboard share header fill, color and type size. Page actions use one outlined rounded button component; Submit results is the single yellow action. Protocol and citation disclosures share their separators and summary scale.

Model details use the same section-heading and prose scales as the pages; metadata stays in the compact YS Text scale. Inline footnote links inherit their text style without adding line spacing. Resource-list links have no extra top margin. The unused inverse-button variant is removed to prevent a conflicting hover cascade.

Catalog tables own their column sizing and horizontal sticky row labels; leaderboard-specific cell and mobile sizing never apply to documentation tables. The catalog scroll hint is shown only while more columns remain to the right. Protocol and citation disclosures use the same right-aligned chevron and full-width native keyboard-operable summary.

Documentation shares a 760px reading measure across introductions, descriptions and notes; the page shell and data tables remain full width. Dataset-group navigation uses aligned three-column link rows (two on phones), the resource-link type scale and visible focus states. Inline API identifiers use monospace without decorative chips. Code examples use a plain square panel up to 920px wide, avoiding needless desktop scrolling, and 13px minimum mobile type; these documentation-specific adaptations preserve native horizontal scrolling and exact copyable code.

Focused scroll regions (catalog, leaderboard, code) explicitly support Left/Right keys across browsers, including WebKit. The handler acts only on the region itself when it overflows; descendant controls, modifiers and composition remain native. This addresses the reproduced WebKit keyboard-scrolling issue (WebKit bug 277290), not a visual redesign.

Catalog and leaderboard use one `data-table` component: 14px YS Text body, 13px/500 headers, 12px secondary labels, 16px row padding and shared horizontal padding (14px desktop, 12px up to 560px). Both use the same header surface, dividers, row hover/focus highlighting, underlined row actions and tabular numerals. Sort buttons have 44px targets; the shared header minimum is 72px. Numeric catalog columns align right. Accessible captions remain available without repeating visible section titles. Column widths, leaderboard vertical sticky headers and its mobile score visibility remain purpose-specific. Best means keep bold emphasis.

Leaderboard focus scrolling accounts for the sticky first column: after native keyboard focus movement, an obscured control is brought fully into the horizontal viewport with a small outline gutter. The check uses live cell geometry, preserves native tab order and ignores stale focus callbacks after rerendering. The correction requires `:focus-visible`, so pointer presses do not move a control before click activation.

Empty and error states use the same left-aligned editorial layout, heading scale and thin separators as the content sections, without a decorative monogram. Table-only explanations disappear together with unavailable or filtered-out results. The native hidden attribute takes precedence over component display rules, including inline-flex links. The code toggle, reset control and dialog close have at least 44px hit areas; mobile search has the same minimum height while retaining 16px input text. These are usability adaptations within the reference's compact visual language.

Selected task tabs are revealed horizontally after URL/history selection, font loading and viewport changes, without moving the page vertically. Modified keyboard shortcuts remain native. Model details open at the start of their content; keyboard-focused links are kept below the close toolbar and inside the scroll viewport, while pointer-focused links remain stationary for reliable clicks. The complete model title scrolls with the details so even a maximum-length name cannot cover the content on a short screen; the close toolbar stays outside that scroll region.

Code and BibTeX panels progressively expose a compact Copy action when the Clipboard API is available. Their square surface, reading width, monospace type and native horizontal scrolling remain shared. Copy uses the exact code text, announces success only after the write resolves, and keeps keyboard focus while pending. Failure gives a manual-copy instruction without moving focus or changing text selection. Without JavaScript or Clipboard API support, the original selectable code remains available.

The off switch uses the existing #666 neutral so its white thumb remains distinguishable (5.74:1); the on state remains black. In forced-colors mode, the switch and close icon use the user's system palette, with explicit borders and focus outlines, without switch color transitions. Automatic color adjustment is overridden only for these system-colored drawings and for a white backing behind the unchanged black logo SVGs. The logo otherwise disappears against a dark forced-color canvas. Current-page navigation gains an underline, and only the selected task/setting tab retains its bottom border: forced colors can otherwise erase the gray active distinction and reveal every transparent border. These targeted adaptations do not constitute a full accessibility certification.

Sortable column names include both visible lines: the dataset and its metric (or Model and Name / variant), followed by the next sort direction. Explicit text-node spaces separate visually stacked labels and model variants without changing flex layout. This keeps spoken/computed names aligned with the table's visible labels; arrows remain decorative.

The task strip also responds to its own size changes, including user font and text-spacing overrides applied after loading. A ResizeObserver reveals the selected task horizontally without moving the document. Ordinary horizontal scrolling does not trigger that observer, so users can browse other tasks freely.

Obsolete hero, breadcrumb, release-grid and resource-list layouts from the former single-page design are removed. The current page system is the source of layout rules; active hero-actions, dataset, result, error, demo and dialog components remain. The cleanup was checked against source class usage, computed styles and paired rendered states rather than inferred from CSS coverage alone.

Retrying a failed data request keeps the retry control and download fallbacks visible. The button shows “Loading…” and uses aria-disabled plus the request guard, preserving focus without duplicate requests. A successful retry moves focus to the loaded results only when focus is still inside the error region being removed; users who moved to another section keep their focus. Another failure leaves the retry action focused and usable.

Printing uses the same fonts with a separate paper layout. Wide tables become sequential two-column records with the current model or dataset repeated at page breaks. Labels, values, links, row order, filters, missing results and best-value emphasis come from the current table; no scores are recomputed. The static dataset catalogue also has print labels without JavaScript. Code wraps, navigation and copy controls are omitted, and closed disclosures remain closed.

An open model prints its complete details in normal document flow. Temporary copies are cleared before every print and after printing; the original dialog, focus, history and content remain intact. Long names and URLs wrap without shrinking the page. Each model result explicitly names its metric, including in the screen dialog. Real A4/Letter PDF checks use Chromium; Firefox and WebKit additionally exercise print styles, ordered data mappings and lifecycle events. These checks do not constitute tagged-PDF or screen-reader certification.

Paper-specific section, record and code-panel spacing is compact enough to avoid footer-only pages in the checked A4 home/catalogue and Letter getting-started views. Font sizes and line heights stay unchanged. Other paper formats may still need an extra page; preserving readable complete sections takes precedence over a fixed page count.

Unavailable dataset columns retain their labels and table alignment, but hide decorative sorting arrows and explain the unsupported setting in their accessible name. The native disabled state remains; switching to a supported setting restores sorting. Result totals use the singular form for one submission.

The initial HTML offers complete CSV and spreadsheet downloads while interactive controls remain hidden. Initialization replaces this fallback only after binding the controls; the same downloads work when JavaScript is disabled or the application script fails to load. If a delayed script replaces a focused fallback link, focus moves to the results panel. Focus elsewhere stays unchanged. The initial View results anchor targets the visible section and upgrades to the filters when ready.

Search filters immediately while continuous input coalesces address updates to at most one every 250ms. The pending value is saved when leaving the field or before a new view/dialog history entry; Back/Forward cancels stale pending updates. Keyboard tab selection is also immediate, while key release, leaving the group or window blur commits only the final view. A full cycle back to the starting view adds no duplicate entry. History traversal cancels the gesture and ignores its remaining repeat events until a fresh press. This avoids the reproduced WebKit history rate limit during long input and held-key navigation without delaying visible results.

While data is loading or unavailable, disabled task tabs remain inside a named, keyboard-focusable scroll region. Left and right arrows scroll that region without changing the selected view. Successful loading transfers focus from the region to its selected tab only if the region still owns focus; focus elsewhere stays put. Setting details and metric labels appear after the payload is available, so deep links do not briefly describe the default RL/Accuracy view.
